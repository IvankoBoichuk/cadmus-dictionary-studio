# ADR-0007: Локальний кеш геоданих замість live-викликів decentralization.ua

- Статус: Accepted
- Дата: 2026-08-17
- Jira: BH-30

## Контекст

BH-30 дозволяє зіставляти історичні географічні позначки словника (форма з оригіналу) із сучасним населеним пунктом, зберігаючи адміністративну ієрархію (область/район/громада, `katottg`/`koatuu`). Джерело істини для сучасного адміністративного поділу — публічний GraphQL/REST API `decentralization.ua`. Пошук і підтвердження зіставлення (AC8, AC10) мають бути швидкими й доступними навіть коли зовнішній сервіс тимчасово недоступний, а `geography` — перший модуль у цьому кодбейзі, що взагалі залежить від зовнішнього HTTP API.

У кодбейзі немає жодної моделі admin/role: `cadmus.identity` описує лише users/credentials/sessions без концепції привілейованого користувача. Це обмежує вибір способу запуску синхронізації.

## Рішення

Окремий модуль `cadmus.geography` — tenant-independent leaf-модуль без залежності на `sources` чи будь-який інший предметний модуль — володіє довідковими таблицями `geography_areas`, `geography_regions`, `geography_communities`, `geography_settlements`, `geography_community_geometries`, `geography_sync_runs`. `SyncGeographyService.sync_all()` повністю витягує areas → regions → communities+settlements через `DecentralizationApiClient` (hand-rolled GraphQL-запити через `httpx`, без GraphQL-клієнтської бібліотеки) і ідемпотентно upsert'ить кожен тип сутності в окремій транзакції (`INSERT ... ON CONFLICT (external_id) DO UPDATE`). Пошук (`SettlementSearchService`) і підтвердження (`SettlementConfirmationService`) читають лише локальний кеш і ніколи не викликають зовнішній API напряму.

Синхронізація запускається виключно вручну через CLI (`make sync-geography`, аналог `backfill-pages`) — без Celery Beat і без HTTP-ендпоінта, що ставив би питання "хто має право це запускати" за відсутності будь-якої моделі ролей. Geometry громади зберігається як провалідований GeoJSON у JSONB-колонці, а не через PostGIS: у кодбейзі немає жодного іншого використання PostGIS, дані geometry лише кешуються для відображення і не потребують просторових запитів (bounding box, intersects тощо).

`sources` отримує нову залежність `sources -> geography` (реальний Python-імпорт з `cadmus.sources.application` у `cadmus.geography.ports`) для читання довідкових даних під час пошуку й підтвердження мапінгу. Зворотної залежності немає: `geography` нічого не знає про `sources`.

`DictionarySettlementMapping` (у `sources`) зберігає власний snapshot ієрархії (`area_name`, `region_name`, `community_name`, `katottg`, `koatuu`), знятий у момент підтвердження, а не живе посилання, що резолвиться щоразу — тож пізніший ресинк чи перейменування в `geography` ніколи не змінює вже підтверджений мапінг заднім числом (AC10, AC12).

## Наслідки

- пошук і підтвердження працюють миттєво й незалежно від доступності `decentralization.ua`;
- партиційний збій синку (наприклад, communities впали, але areas/regions уже засинкались) не відкочує раніше успішні типи сутностей і не блокує вже наявні дані (AC15, AC17);
- дані можуть застаріти між ручними запусками `make sync-geography` — прийнятно, бо адміністративний поділ змінюється рідко, а оператор явно контролює момент ресинку;
- підтверджені мапінги стабільні до FK навіть після ресинку завдяки diff-based (а не delete-then-reinsert) upsert `geography_settlements`;
- перший вихідний HTTP-виклик у кодбейзі (`httpx`) — потребує обмеженого retry з backoff лише на мережевих/5xx помилках, ніколи на 4xx.

## Відхилені альтернативи

- live-виклик `decentralization.ua` при кожному пошуку/підтвердженні: залежність продуктивності й доступності від зовнішнього сервісу, немає офлайн-стійкості;
- Celery Beat-розклад для автоматичного ресинку: додає окремий compose-сервіс і періодичну задачу заради функції, якій достатньо ручного запуску, поки продукту не потрібна свіжість даних у реальному часі;
- HTTP-ендпоінт для запуску синку: вимагав би вигадати концепцію "адміністратора", якої немає ніде в системі — свідомо відкладено до появи реальної потреби в ролях;
- PostGIS для geometry громад: зайва інфраструктурна залежність заради даних, які лише відображаються, а не запитуються просторово.
