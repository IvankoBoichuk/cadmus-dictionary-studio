# ADR-0003: Провайдерно-незалежний versioned pipeline

- Статус: Accepted
- Дата: 2026-08-13
- Jira: BH-175

## Контекст

Якість OCR залежить від словника. Проєкт має почати з Tesseract, але дозволяти порівняння з Kraken, PaddleOCR або хмарними сервісами. Науковий результат повинен бути відтворюваним і пов'язаним із джерелом.

## Рішення

OCR, preprocessing, layout і extraction підключаються через application ports. Кожний `ProcessingRun` зберігає input checksum, pipeline/stage versions, provider/model version та config hash. Етапи є ідемпотентними й створюють versioned artifacts. Канонічний OCR-контракт містить текст, геометрію, confidence та посилання на raw output.

## Наслідки

- провайдер можна замінити без зміни домену;
- експерименти стають порівнюваними;
- потрібні адаптери й нормалізація координат;
- схему канонічного результату необхідно версіонувати.

## Відхилені альтернативи

- пряме використання Tesseract DTO у домені: створює vendor coupling;
- VLM як єдине джерело істини: недостатня відтворюваність і ризик вигаданих полів.
