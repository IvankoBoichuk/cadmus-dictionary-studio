# Web client instructions

These rules apply under `apps/web/` in addition to the repository instructions.

## Design

- React components never call `fetch` directly. Add typed operations to the shared API facade.
- Derive request and response types from the generated OpenAPI contract.
- Parse and normalize HTTP, network, and malformed-response failures in the shared transport.
- Pass abort cancellation through the shared transport.
- Put non-trivial form state, validation, submission, and API-error mapping in a focused hook.
- Put lifecycle-bound asynchronous workflows in focused hooks and expose discriminated state.
- Account for React Strict Mode when effects trigger one-time mutations.
- Add dependencies only for demonstrated current complexity, not anticipated reuse.

`src/api/schema.d.ts` is generated by `make web-api-types`. Never edit or read the complete file unless the Story changes the OpenAPI contract or generated type mapping. Prefer the stable types exported by `src/api/index.ts`.

## Targeted verification

During implementation, prefer the narrowest useful commands:

~~~bash
cd apps/web && bunx vitest run path/to/changed.test.tsx
cd apps/web && bun run lint
cd apps/web && bun run type-check
~~~

Run `make web-api-types-check` only when API operations or schemas change. Run `make web-build` when build behavior, routing, configuration, or production output may be affected. Accessible interaction tests are required for changed user flows.
